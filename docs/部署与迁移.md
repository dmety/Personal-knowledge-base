# Sites 自部署、备份与迁移

## 前提与本地运行

需要 Node.js 24 LTS、Git、支持 Sites 的账号和已连接的 Sites 插件。Sites 提供 Worker 托管、可信身份认证、D1、R2 和个人 MCP 插件。平台权限、额度和价格以你的账号显示为准。

先完成 README 的本地步骤。`npm run build` 生成本地 Worker 配置；`npm run db:migrate:local` 按迁移日志执行全部结构迁移，重复执行只应用尚未应用的迁移。`npm run dev` 启用只限回环地址的模拟登录。不要把开发服务器暴露到公网。

## 创建你自己的线上资源

在 Codex 中打开自己的克隆目录，使用 Sites 插件并发出以下请求：

> 请把这个仓库部署到我自己的新 Sites 实例。先读取 Sites 技能和 .openai/hosting.json；只有没有 project_id 时才创建站点。使用我自己的 D1（DB）和 R2（BUCKET），保留 mcp 能力，设为仅本人可访问。把返回的项目 ID 写回当前克隆，使用 Sites 原生源码同步、构建打包和发布流程。不要使用其他人的实例或资源。发布后提供个人插件连接入口，并用只读检索验证。

仓库中的 `.openai/hosting.json` 初始只有：

```json
{"d1":"DB","r2":"BUCKET","capabilities":["mcp"]}
```

Sites 创建站点后，使用原生 `set-project-id.mjs` 写入返回的真实 ID，或运行 `npm run site:init -- --project-id <Sites返回的ID>`。这个命令只写配置，不创建、连接或部署任何资源；已绑定其他 ID 时拒绝覆盖。

后续发布先读取当前克隆的 ID 并查询同一站点，复用资源。创建超时先核对是否已登记，避免重复创建。只使用同一项目的临时源码凭据，通过 Sites 工作流隐藏 stdin 传递；不提交或打印凭据。线上结构迁移由 Sites 发布流程执行，不用本地迁移命令操作生产库。

这些操作由部署者账号中的 Sites 工具完成，复制模板不是“部署成功”。完成后确认平台部署终态、URL、仅本人访问策略及 D1/R2 绑定。自己的项目 ID 可留在私有部署克隆，准备再次公开分享时移除实例绑定。

## 连接自己的个人插件

发布包含 `/mcp` 后，Sites 会为该实例生成个人插件。读取 `get_site(include_mcp_connection=true)`，只使用本次部署返回的插件 ID 显示安装入口；或打开 **Plugins > Personal > Created by you**，选择自己的实例，Install / Connect 并完成认证。

GitHub 的知序技能包提供操作指导，不替代这个数据连接。连接后确认当前工具来自自己的实例，并调用 `search_knowledge` 做只读检索。空库返回空结果是正常的。没有完成实际调用时，只能报告“站点已部署，插件连接待验证”。

生产依赖 Sites 可信身份与访问策略，不能通过手填身份头或开放权限绕过认证。GitHub 不托管你的数据库，作者不会为你的部署提供资源或连接凭据。

## 备份与恢复

完整 ZIP 包含 backup.json、entries/ Markdown 和 assets/ 附件。JSON 不包含附件二进制；有附件时应使用完整 ZIP 恢复。备份需要保存在自己的私有位置，不能提交到 GitHub。

ZIP 附件总量 60 MB，导入文件和解压总量 80 MB，单次最多 300 条。更大数据集需按依赖关系分批备份或使用授权的存储导出流程；不要把截断的查询结果当作备份。

导入先预览。重复 ID 默认跳过；替换需明确勾选并保留历史。缺失附件、未解决关联或同 ID 不同附件会阻止导入。失败重试不能覆盖其他文件。导出成功不代表浏览器已经保存，请确认下载完成。

跨实例恢复时，必须由部署者在新身份下导入；不同 Sites 的用户 ID 不相等，不能照搬原站命名空间。移出 Sites 还需要实现可信认证、owner 授权和 MCP OAuth；本版不提供此路径的即用配置。
